# 08 · 安全与审批

> 来源：文档第 9 节。第一阶段仅本机 / 受控网络运行，**未完成认证前禁止暴露公网**。

## 1. 权限分级（已落地为策略模块）

| 等级 | 允许 | 代码 |
|---|---|---|
| L1 | 查询、整理、分析 | `assertAllowed` 白名单 |
| L2 | 生成草稿、计算、保存 | 同上 |
| L3 | 经批准后执行外部操作 | `requireApproval()` 闸门 |
| L4 | 禁止 AI 自主执行 | 一律 403 |

## 2. 审批闸门（F-11 已可验证）

- 将项目改为 `archived` 属于 L3 破坏性操作
- `PATCH /api/v1/projects/:id` 会检查 `audit_logs` 中是否存在
  `action=approve AND entity_type=project AND entity_id=<id>` 的记录
- 无记录 → `403 APPROVAL_REQUIRED`，操作被阻止
- 有记录 → 允许执行，并写入 `archive` 审计日志
- 代码里**没有后门**，不能在未审批时自行放行

集成测试 `tests/integration/permissions.test.ts` 覆盖「阻止」与「批准后放行」两条路径。

## 3. 必须记录的日志（文档 9.2）

已落地：`create` / `update` / `delete` / `archive` / `approve` / `reject` / `run`（写入 `audit_logs`）。
执行链路另有 `agent_runs` / `agent_messages` / `task_logs` 三张表，文件有 SHA-256 校验和。

| 要求 | 状态 |
|---|---|
| API Key 放环境变量、.env 不提交 | ✅ `.env.local` 已忽略，`!.env.example` 保留 |

## 5. 成本红线

- 默认 `AI_PROVIDER=none`：不调用任何模型
- 外部/付费模型适配器**未实现**，尝试启用返回 403
- 未安装付费软件、未创建云资源、未公开代码仓库
- Agent 不能自行决定购买付费服务

## 6. 已知风险

1. **无登录认证**：本机与局域网内任何能访问该端口的人都能读写全部数据。局域网自用可以，**禁止公网暴露**（不要做端口映射、不要用内网穿透）。
2. 审批记录仍复用 `audit_logs`（`approvals` 表已建但未接入闸门），后续迁到独立表并加完整审批流。
3. 尚无 CSRF token、速率限制与 CSP。接口要求 `Content-Type: application/json` 只能缓解一部分 CSRF；对外提供服务前必须补齐。
4. 局域网模式下，防火墙放行的是端口而不是身份——同一 Wi-Fi 下的其他人只要知道地址就能进。
