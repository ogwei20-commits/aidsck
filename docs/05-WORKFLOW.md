# 05 · 工作流设计

> 来源：文档第 8 节。当前状态：**未实现执行引擎**，仅登记设计。

## 1. 核心工作流：跨境电商创业可行性研究

| 节点 | 动作 | Sprint |
|---|---|---|
| 1 | 创建研究项目 | S3 |
| 2 | 收集用户目标 | S4 |
| 3 | 生成研究任务 | S4 |
| 4 | Market Analyst 执行 | S4/S5 |
| 5 | Platform Analyst 执行 | S5 |
| 6 | Product Researcher 执行 | S5 |
| 7 | Finance Analyst 执行 | S5 |
| 8 | 供应链与合规研究 → 后续扩展 | Phase 2 |
| 9 | 汇总研究发现 | S5 |
| 10 | 检查证据与数据类型 R/E/P/S/U | S5 |
| 11 | 交叉审核关键结论 | S5 |
| 12 | 生成研究报告 | S5 |
| 13 | 用户审核（人工闸门） | S5 |
| 14 | 保存知识 | S5 |
| 15 | 更新成长档案 | S6 |

## 2. 第一阶段约束

- **不做复杂可视化流程设计器**（文档 8 明确）
- 先实现可配置的基础工作流执行引擎
- 每个节点必须通过受控工具调用，执行记录写入 `agent_runs` / `workflow_runs`
- 节点 13 的人工审核不可跳过；L3 操作受审批闸门保护

## 3. 当前可验证的近似流程

```
首屏输入目标 → POST /api/v1/tasks → 写入 tasks → 写 audit_logs
             → router.refresh() → 首页「今日任务」真实出现
```

这不是工作流引擎，不冒充可实现节点 1–15。
