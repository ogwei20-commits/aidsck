# V2 重做记录：方向 / 配色 / 文案 / 范围

> 触发：V1 交付后收到的四条反馈 —— 方向想换、位置配色文案不对、功能范围少了。
> 本文件只记录「改了什么、为什么改、怎么验证」，不重复 README 的说明。

## 一、你提的问题 → 实际改动

### 1. 方向想换（三个方向都要）

V1 是「监控台」：深色侧栏 + 通栏深色首屏 + 等宽数字，工程感重。

只换皮不解决问题，所以重做了信息架构。三个方向不是平铺成三块，而是串成一条因果链：

| 位置 | 承担哪个方向 | 具体做法 |
|---|---|---|
| 首屏（唯一主角） | AI 对话工作台 | 一句话输入 → 拆成任务 → 落到任务中心，结果在下方展开 |
| 第二屏 | 生意驾驶舱 | 4 个数字（在跑项目 / 待处理 / 单件净利 / 已沉淀）+ 项目与任务双栏 |
| 第三屏 | 学习 + 执行双轨 | 左「该做的」任务时间线，右「该学的」计划进度，底部各有汇总 |
| 第四屏 | — | 6 个 Agent 的真实状态（注册了 ≠ 跑过，未跑就写未运行） |
| 第五屏 | — | 报告与知识条目 |
| 第六屏 | — | 三条真实边界（AI 未接入、无认证、文件只登记） |

### 2. 位置不对

根因：V1 首页把「模块交付状态 · S = Sprint」「数据类型说明」这类**验收清单**放在了业务内容位置——那是写给我自己看的。

改动：这两块从首页移出。「模块交付状态」并入数据溯源页的真实统计，「数据类型标准」放数据溯源页。

### 3. 配色不对

V1 是青绿 `#0b6e7a` + 米灰纸底 `#fbfaf7`，是笔记/法务工具的调子。

改动：三套可选配色，切换写 cookie，刷新不丢。

| 方案 | 主色 | 底 | 感觉 |
|---|---|---|---|
| 深色专业 | `#4a9eff` | `#0d1117` | 信息密度高，AI 工具感 |
| 浅色琥珀 | `#b45309` | `#fdfbf7` | 贸易与钱的味道 |
| 浅色靛蓝 | `#4338ca` | `#f7f8fb` | 稳重企业感 |

技术上：组件不写死颜色，全部走语义变量。侧栏另有 `--side-*` 独立变量——因为 V1 修配色时踩过一个坑：浅色主题下侧栏仍用 `--band` 深底，导航文字几乎不可读（截图确认后已修）。

### 4. 文案不对

V1 的问题是把「开发说明」当成了产品文案：

| V1 原文 | V2 |
|---|---|
| 今天有 3 件事等你处理 | 有 8 件事等着你拍板 |
| 任务、项目与每一条操作记录都写进本机 PostgreSQL，关掉页面也不会丢；规划中的能力一律标明，不拿静态页面冒充功能 | 不用一次想清所有步骤。说一句你现在最想解决的事，剩下的拆解、派活、记账交给系统。 |
| PHASE 1 / SPRINT 1 · 本地工作台 | 今天 · 11月15日星期六 |
| 模块交付状态（S = Sprint） | 已移除 |

诚实说明没有删，只是降级成小字：「拆解来自内置研究流程模板，不调用模型、不产生费用」——放在按钮旁，不占标题。

### 5. 范围少了

V1 只有 3 个模块真能用，其余 16 个是「规划中」空壳。

改动：**一个通用内核 + 19 份模块定义**，而不是手写 19 套。

- 数据层：39 张表，覆盖文档 4.2 全部清单（`src/db/schema/` 七个域文件）
- 接口层：`/api/v1/modules/[module]` 一套 CRUD 服务 15 个模块
- 页面层：`/[section]` 一个动态路由渲染全部模块

新增模块只需要在 `src/modules/defs/` 写一份定义（字段、列、空态文案），API 与页面自动可用。

**安全**：表名与列名只来自注册表白名单，外部字符串不进入 SQL 标识符位置，值全部参数绑定。

财务模块额外补了计算：输入成本售价 → 单件总成本 / 单件净利 / 利润率 / 盈亏平衡单量，假设与币种同行显示。

## 二、修掉的三个真缺陷

| 缺陷 | 现象 | 根因 | 修法 |
|---|---|---|---|
| Client 包引入服务端 API | 构建失败：`next/headers` 被打进浏览器包 | `theme-switch.tsx` 直接 import 了含 `cookies()` 的模块 | 常量拆到 `theme-shared.ts`，服务端方法留在 `theme.ts` 并加 `server-only` |
| 主题切换触发不可变规则 | Lint 报 `This value cannot be modified` | 在事件处理里直接改 `document` | 改为 state + `useEffect` 同步 DOM 与 cookie |
| 财务口径错误 | 用「单件其他费用」当固定投入算盈亏平衡 | 表里缺固定投入字段 | 新增 `fixed_cost` 列（迁移 0002），公式改为 `ceil(固定投入 / 单件净利)`，固定投入为 0 时明确说「无法给出」而不是返回 0 |

第三个缺陷连带修正了演示报告里「净利 3.9 / 月销 600 单」的错数字 → 实算 2.84 / 1058 单。
