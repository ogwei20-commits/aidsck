# 08 · 安全与审批

> 来源：文档第 9 节。第一阶段仅本机 / 受控网络运行，**未完成认证前禁止暴露公网**。

## 1. 权限分级（已落地为策略模块）

| 等级 | 允许 | 代码 |
|---|---|---|
| L1 | 查询、整理、分析 | `assertAllowed` 白名单 |
| L2 | 生成草稿、计算、保存 | 同上 |
| L3 | 经批准后执行外部操作 | `requireApproval()` 闸门 |
| L4 | 禁止 AI 自主执行 | 一律 403 |

## 2. 审批闸门（F-11 已可验证）

- 将项目改为 `archived` 属于 L3 破坏性操作
- `PATCH /api/v1/projects/:id` 会检查 `audit_logs` 中是否存在
  `action=approve AND entity_type=project AND entity_id=<id>` 的记录
- 无记录 → `403 APPROVAL_REQUIRED`，操作被阻止
- 有记录 → 允许执行，并写入 `archive` 审计日志
- 代码里**没有后门**，不能在未审批时自行放行

集成测试 `tests/integration/permissions.test.ts` 覆盖「阻止」与「批准后放行」两条路径。

## 6. 已知风险

1. 当前是**单人本地环境，无登录认证**，任何能访问 localhost 的人都能读写数据 —— 禁止公网暴露。
2. 审批记录复用了 `audit_logs`，S4 需迁到独立 `approvals` 表并加审批流（迁移可回退）。
3. 尚无 CSRF / 速率限制 / CSP；这些在对外提供服务前必须补齐。
